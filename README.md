# FPV Frequency Manager

**Автономний програмний комплекс розрахунку та координації частот відеоканалів FPV БПЛА**  
*Розробка: Команда Дизармерів Ф-22 • Версія специфікації: 2.0 • Стандарт: MIL-STD / FPV Tactical*

[Публічний доступ (PWA)](https://khronosXP.github.io/fpv-freq-manager/) • [Збірка та CI/CD](https://github.com/khronosXP/fpv-freq-manager/actions) • [Технічна специфікація](#2-фізико-математична-модель)

## 1. Загальні відомості

FPV Frequency Manager — спеціалізоване програмне забезпечення класу Offline-First PWA, розроблене для автоматизованої радіочастотної координації групових польотів безпілотних авіаційних комплексів (до 12 бортів одночасно).

Система розв'язує задачу синтезу неінтерферуючої частотної сітки в діапазонах 4.9–5.8 GHz з математично доведеним захистом від:
1. Прямого взаємного накладання спектрів (Adjacent Channel Interference).
2. Інтермодуляції третього порядку (Third-Order Intermodulation Distortion, IMD3) у приймальних трактах (VRX).

> [!IMPORTANT]
> **Автономність застосування**: Додаток є повністю незалежним від зовнішніх серверів, хмарних API чи інтернет-з'єднання. Кешування забезпечується за стандартом Progressive Web App (Service Worker + Cache Storage).

## 2. Фізико-математична модель

### 2.1. Критерій захисного інтервалу (Guard Band)
Для аналогового композитного відеосигналу (PAL/NTSC), що модулюється за частотою (WFM), необхідна ширина смуги випромінювання $B_n$ за правилом Карсона становить:
$$B_n = 2 (\Delta f_{pk} + f_m) \approx 27\text{–}30\text{ MHz}$$
де $\Delta f_{pk}$ — пікова девіація частоти (~8 MHz), $f_m$ — максимальна частота модулюючого сигналу з урахуванням піднесучої аудіо (~6.5 MHz).

Для запобігання перевантаженню та просочуванню потужності у смугу проміжної частоти (IF) сусідніх приймачів встановлено обов'язковий захисний бар'єр:
$$\Delta f_{ij} = |f_i - f_j| \ge 40\text{ MHz}, \quad \forall i \ne j$$

### 2.2. Модель придушення інтермодуляції 3-го порядку (IMD3)
При одночасній роботі двох потужних передавачів $f_1$ та $f_2$ поблизу приймальної антени, на нелінійних елементах вхідного підсилювача (LNA) та першого змішувача приймача формуються паразитні продукти комбінаційних частот 3-го порядку:
$$f_{\text{IMD3}} = 2f_i - f_j, \quad i \ne j$$

Якщо комбінаційна частота потрапляє у смугу прийому третього борта $f_k$, виникає фазове спотворення, збій рядкової синхронізації або повна втрата відеосигналу. Система гарантує дотримання рознесення:
$$\delta_{\text{IMD3}} = |(2f_i - f_j) - f_k| \ge 10\text{ MHz}, \quad \forall i, j, k \text{ (попарно різні)}$$

### 2.3. Поляризація
Розрахунок регламентовано для використання антенного обладнання з правою круговою поляризацією (**RHCP**). Ефект поляризаційної ізоляції (~15–20 dB відбитих сигналів) підсилює апаратну стійкість каналів.

## 4. Алгоритмічне ядро (Zero-Latency Engine)

Розрахунок базується на детермінованому алгоритмі бектрекінгу з двома рівнями оптимізації складності:

1. **Symmetry Breaking (Усунення перестановок)**:  
   Оскільки бортовий пул одного класу має еквівалентні апаратні обмеження, перебір каналів здійснюється у строго монотонному порядку індексів ($i_k > i_{k-1}$). Це редукує простір пошуку від розміщення $P(n, k)$ до комбінацій $C(n, k)$, знижуючи обчислювальну складність у $k!$ разів.
2. **Early Capacity Pruning (Раннє відсікання)**:  
   Неможливі конфігурації (наприклад, $N_{\text{standard}} > 6$ або $N_{\text{total}} > 12$) відсікаються на стадії ініціалізації за $O(1)$.
3. **Часові характеристики**:  
   Час виконання повного розрахунку на мобільних пристроях становить **0.5 – 9 ms**, що виключає затримки інтерфейсу та блокування головного потоку рендерингу (UI thread).

## 5. Архітектура та програмний стек

- **Клієнтська платформа**: Flutter 3 (Web, Android, Desktop)
- **Архітектурний патерн**: Clean Architecture (Presentation, Domain/Core, Math)
- **Управління станом**: Riverpod 2 (`NotifierProvider` з оптимістичною синхронізацією)
- **Графічна підсистема**: CustomPainter (апаратне прискорення через CanvasKit / Skia)
- **Дизайн-система**: Material 3 High-Contrast Dark UI (оптимізовано для польових дисплеїв високої яскравості)

### Структура проекту

```
lib/
├── core/
│   ├── constants/       # Частотні таблиці та параметри діапазонів
│   ├── math/            # Алгоритми IMD3-валідації та розподілу частот
│   └── models/          # Доменні моделі (AssignedBoard, FpvChannel, BoardType)
└── presentation/
    ├── providers/       # Стейт-машина калькулятора (Riverpod Notifier)
    ├── screens/         # Екрани застосунку (CalculatorScreen)
    ├── theme/           # Контрастна тема інтерфейсу (AppTheme)
    └── widgets/         # Модульні віджети (Chart, CheatSheet, Counters, Banners)
```
